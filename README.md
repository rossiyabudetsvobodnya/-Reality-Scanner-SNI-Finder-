# -Reality-Scanner-SNI-Finder-
Автоматический сканер и база проверенных SNI-доменов (TLS 1.3 + HTTP/2) для настройки VLESS + XTLS-Reality на базе GitHub Actions
# 🔍 Свобода от Орды — Reality SNI Finder

Инструмент и регулярно обновляемый каталог проверенных доменов маскировки (**SNI**) для протокола **VLESS + XTLS-Reality**. Проект использует вычислительные мощности **GitHub Actions** для сканирования, проверки TLS-рукопожатий и отбора самых стабильных целей.

---

## 🎯 Зачем это нужно

Для стабильной работы **XTLS-Reality** целевой сайт маскировки должен отвечать строгим требованиям:
* Поддержка протокола **TLS 1.3** и **HTTP/2 (h2)**.
* Отсутствие агрессивных редиректов и WAF-заглушек, ломающих handshake.
* Минимальная сетевая задержка (желательно в том же ASN / дата-центре, что и ваш VPS).

Этот репозиторий избавляет от ручного подбора — свежие списки уже отфильтрованы и готовы к вставке в настройки **3x-ui**, **Marzban** или чистого **Xray-core**.

---

## 📋 Готовые списки (обновляются через GitHub Actions)

* `lists/top-sni.txt` — универсальные, проверенные SNI с высокой доступностью и TLS 1.3 + H2.
* `lists/hetzner-sni.txt` — домены, размещённые в подсетях Hetzner (DE / FI).
* `lists/aeza-digitalocean-sni.txt` — цели для популярных европейских площадок (NL / DE).
* `lists/report.json` — подробный технический отчёт (версия TLS, ALPN, время ответа, статус-код).

---

## ⚙️ Как работает сканер

1. **GitHub Actions** запускает Python-скрипт (`scanner.py`) по расписанию или по ручному триггеру (`workflow_dispatch`) с указанием нужного CIDR-диапазона или списка доменов.
2. Скрипт асинхронно проверяет SSL-сертификаты, поддержку `TLSv1.3` и `h2`, а также измеряет время ответа сервера.
3. Отсеиваются домены с устаревшим шифрованием или блокировками.
4. Обновлённые списки автоматически коммитятся в репозиторий.

---

## 🚀 Запуск своего сканирования через GitHub Actions

1. Сделайте **Fork** этого репозитория.
2. Перейдите во вкладку **Actions → Scan Reality SNI**.
3. Нажмите **Run workflow**, впишите нужный домен, список или IP-подсеть (например, `185.x.x.0/24`).
4. Через пару минут заберите готовый список идеальных SNI в папке `lists/`.
